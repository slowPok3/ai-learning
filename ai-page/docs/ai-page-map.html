One parse, four views. The Markdown is parsed exactly once, at bootstrap:
course-curriculum.md→ build-curriculum.js→ course-curriculum.js→ parseCurriculum()→ curriculumModel
curriculumModel and palette are then handed to every view's activate(model, palette) — no view re-parses the Markdown itself.
Panel Owns the shared side-panel. Doesn't reference any view's internals — a view that needs to re-fit itself when the panel opens or closes registers a callback via Panel.onResize(fn) instead, so CosmosView and MindmapView can be swapped or removed without touching panel.js.

Checked & ruled out

Knowledge Web's tooltip passes unescaped curriculum text into vis-network, but the pinned vis-network 10.1.0 build uses .innerText (verified against the actual bundle) — a safe, text-only sink. Adding escapeHtml() there would be a regression: innerText doesn't decode entities, so it would show a literal &amp; instead of &.
